# Milestone Plans — Index

Infinite-canvas drawing POC (Excalidraw-style), a **learning project** built strictly **one milestone at a time**. Each milestone gets its **own** plan file in this directory, authored when we start that milestone (we do not pre-write future milestones).

**Category legend:** **[A]** = the user writes the core logic themselves (Claude gives interface + concept + review, not the implementation). **[B]** = Claude writes it (scaffolding/boilerplate). See `working-style` in project memory. **From M14 on the split is dropped:** Claude writes everything (Category column reads "Claude").

> Notes: M0–M7 are complete — runtime design is documented in `ARCHITECTURE.md`. M5 shipped all three draw tools (rectangle, ellipse, freehand). M6 added `src/core/scene/hit-test.ts` (point-in-rect/ellipse, near-path). M7 replaced the M6 console probe with real single-select: a separate `src/core/editor/store.ts` (`createEditorStore`, id-based selection), `src/core/scene/bounds.ts` (`getBoundingBox`), a `drawSelectionBox` overlay, plus Escape-to-deselect, hover cursor, and auto-select-after-draw. M8 added `src/core/scene/translate.ts` (`translateElement`), `replaceElement` on the scene store (index-preserving, so a move never changes z-order), and `src/react/useSelectTool.ts` — select and drag-to-move split out of `useDrawTool`, sharing `src/react/pointer.ts`. Dragging commits live to the store (ADR-0002); **arrow-key nudge was deliberately deferred** and can be picked up any time. Plan files for M3→M4 and M5 were not retained — they lived only in the transient `~/.claude/plans/` scratch directory. Every plan from M6 on is versioned here. M9 added `src/core/persistence/local-storage.ts` (`persistScene` / `loadScene`, one key, bare JSON array) plus the seed-and-subscribe wiring in `CanvasBoard`, and a **Persistence** section to `CONTEXT.md`. It is **deliberately naive** — no schema version, no validation, no error handling, no coalescing — because M10 exists to break it; the omissions and their reasoning are decisions 1, 5 and 8 of its plan. No ADR, by decision. M10 broke it on purpose and fixed nothing: it added `src/core/persistence/diagnostics.ts` (deterministic stress scenes, storage-cost measurement, a binary-search quota probe, a flood that drives the real write path until it throws, and three deliberate corruptions) plus a dev-only `window.canvasDiagnostics` handle via `src/react/useDiagnostics.ts`. `local-storage.ts` was not touched. The measurements — Chrome 143, recorded in [`m10-findings.md`](m10-findings.md) — found a 5 MiB **per-origin** quota charged in *characters* (not bytes, which the plan initially assumed), ≈431 freehand strokes before it fills, silent permanent data loss once it does, a 15–17 ms whole-scene write per `pointermove` at 200 strokes, and three load-time failures of which two are entirely silent. They produced **ADR-0003 (IndexedDB)**, which M11 implements along with the version envelope and validation M9 left out. M11 answered all four of M10's failures in one pass ([`m11-indexeddb-persistence.md`](m11-indexeddb-persistence.md); Category A waived for this milestone only). The scene is now one whole-scene IndexedDB record, `{ version: 1, elements }`; `local-storage.ts` is gone and the old key is removed unread on every boot. The load is asynchronous but Suspense-gated, so the store is still born holding the document. A document that fails the all-or-nothing validator is quarantined, intact, behind a notice (**ADR-0004**). Writes go through a debounced persister that flushes on hide, and the user is told whenever the drawing is not being saved. **Multiple tabs are a documented known limitation** (last writer wins). ADR-0003's claim that serialisation leaves the main thread was corrected by a dated amendment: `put()` structured-clones synchronously. [`m11-findings.md`](m11-findings.md) measured it against M10's W2 — 34–48% cheaper from 100 strokes up, still more than a frame at 400 — which is why coalescing stays. The runtime design, including which diagnostics were kept, retargeted and removed, is in `ARCHITECTURE.md` ("Persistence"). M12 added resize and delete ([`m12-resize-delete.md`](m12-resize-delete.md); Category A waived for this milestone only, with the standing instruction to code very simply). In the select tool, eight screen-px handles sit on the selection box, corners first so a corner wins where they overlap; `getHandles` in `selection.ts` is the one list both drawing and hit-testing use. A drag recomputes a target box from the original element with the anchor fixed, clamps only the axes the handle changes to `MIN_ELEMENT_SIZE` (moved out of `useDrawTool` into `src/core/scene/resize.ts`), and commits `fitElement`'s result live. A negative target size is a flip, and freehand strokes stretch, keeping factor 1 on a flat axis. **No new ADR**: ADR-0002 applies unchanged. Delete or Backspace deletes the selection in any tool, except mid-press (`src/react/useDeleteKey.ts`), through a new `removeElement` on the scene store that knows nothing about selection. Shift/Alt resize modifiers were left out and can be picked up any time. Two consequences carry into M13: restoring a deleted element needs its old index to keep z-order, and a resize, like a move, must be undone as one gesture. The runtime design is in `ARCHITECTURE.md` ("Resizing", "Deleting"). M13 added undo and redo ([`m13-undo-redo.md`](m13-undo-redo.md); Category A waived for this milestone only). Ctrl/Cmd+Z undoes one whole editor action (a draw, a move, a resize or a delete), and Ctrl/Cmd+Shift+Z or Ctrl+Y redoes it. The brief asked for a command stack with event sourcing as the concept, and **ADR-0005** records the choice between them: a linear stack of plain-data **history entries**, each a scene operation (`add`, `replace`, `remove`), applied through the scene store, which stays the source of truth. Event sourcing was rejected because it would have rebuilt persistence to get undo. `src/core/history/history.ts` (`createHistory(store)`) holds the stacks. The scene store gained `insertElement`, and `removeElement` now returns the index it removed from, so a deleted element comes back at its old depth. Nothing diffs the store: the owner of each action records it when it finishes (`useSelectTool`, `useDrawTool`, the delete key), and a test that undoing a mixed run of every kind returns the starting scene backs that pattern up in core. `useDeleteKey` became `src/react/useEditorKeys.ts`, which handles Delete, Backspace, undo and redo in any tool, all ignored mid-press. After an undo or redo, the entry's element is selected if it is in the scene. History is not persisted and has no size limit. With M13 the original roadmap was complete. M14–M17 extend it with four features that, as far as we know, Excalidraw and tldraw don't offer. They are built in that order: the timeline first, while M13 is fresh; then the eraser, which needs history to hold one action that changes several elements; then recognition; then beacons, which touch only the viewport. Each gets its own plan file when it starts. The runtime design is in `ARCHITECTURE.md` ("History").
