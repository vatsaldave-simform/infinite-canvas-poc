# Milestone Plans — Index

**Category legend:** **[A]** = the user writes the core logic themselves (Claude gives interface + concept + review, not the implementation). **[B]** = Claude writes it (scaffolding/boilerplate). See `working-style` in project memory.

> Notes: M0–M7 are complete — runtime design is documented in `ARCHITECTURE.md`. M5 shipped all three draw tools (rectangle, ellipse, freehand). M6 added `src/core/scene/hit-test.ts` (point-in-rect/ellipse, near-path). M7 replaced the M6 console probe with real single-select: a separate `src/core/editor/store.ts` (`createEditorStore`, id-based selection), `src/core/scene/bounds.ts` (`getBoundingBox`), a `drawSelectionBox` overlay, plus Escape-to-deselect, hover cursor, and auto-select-after-draw. M8 added `src/core/scene/translate.ts` (`translateElement`), `replaceElement` on the scene store (index-preserving, so a move never changes z-order), and `src/react/useSelectTool.ts` — select and drag-to-move split out of `useDrawTool`, sharing `src/react/pointer.ts`. Dragging commits live to the store (ADR-0002); **arrow-key nudge was deliberately deferred** and can be picked up any time. Plan files for M3→M4 and M5 were not retained — they lived only in the transient `~/.claude/plans/` scratch directory. Every plan from M6 on is versioned here. M9 added `src/core/persistence/local-storage.ts` (`persistScene` / `loadScene`, one key, bare JSON array) plus the seed-and-subscribe wiring in `CanvasBoard`, and a **Persistence** section to `CONTEXT.md`. It is **deliberately naive** — no schema version, no validation, no error handling, no coalescing — because M10 exists to break it; the omissions and their reasoning are decisions 1, 5 and 8 of its plan. No ADR, by decision. M10 broke it on purpose and fixed nothing: it added `src/core/persistence/diagnostics.ts` (deterministic stress scenes, storage-cost measurement, a binary-search quota probe, a flood that drives the real write path until it throws, and three deliberate corruptions) plus a dev-only `window.canvasDiagnostics` handle via `src/react/useDiagnostics.ts`. `local-storage.ts` was not touched. The measurements — Chrome 143, recorded in [`m10-findings.md`](m10-findings.md) — found a 5 MiB **per-origin** quota charged in *characters* (not bytes, which the plan initially assumed), ≈431 freehand strokes before it fills, silent permanent data loss once it does, a 15–17 ms whole-scene write per `pointermove` at 200 strokes, and three load-time failures of which two are entirely silent. They produced **ADR-0003 (IndexedDB)**, which M11 implements along with the version envelope and validation M9 left out. M11 answered all four of M10's failures in one pass ([`m11-indexeddb-persistence.md`](m11-indexeddb-persistence.md); Category A waived for this milestone only). The scene is now one whole-scene IndexedDB record, `{ version: 1, elements }`; `local-storage.ts` is gone and the old key is removed unread on every boot. The load is asynchronous but Suspense-gated, so the store is still born holding the document. A document that fails the all-or-nothing validator is quarantined, intact, behind a notice (**ADR-0004**). Writes go through a debounced persister that flushes on hide, and the user is told whenever the drawing is not being saved. **Multiple tabs are a documented known limitation** (last writer wins). ADR-0003's claim that serialisation leaves the main thread was corrected by a dated amendment: `put()` structured-clones synchronously. [`m11-findings.md`](m11-findings.md) measured it against M10's W2 — 34–48% cheaper from 100 strokes up, still more than a frame at 400 — which is why coalescing stays. The runtime design, including which diagnostics were kept, retargeted and removed, is in `ARCHITECTURE.md` ("Persistence").
